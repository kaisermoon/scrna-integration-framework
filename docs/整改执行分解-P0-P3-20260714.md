## 一、贯穿铁律：expression_contract schema（P0 先定，全阶段引用）

所有 counts 契约实现同一份 schema，写在 `adata.uns["expression_contract"]`。**这是 per-file 并行开发能收敛的前提**——各 notebook 只要实现同一 schema 就不会互相冲突。

```python
adata.uns["expression_contract"] = {
    "x_scale": "raw_counts" | "normalized_log1p",   # X 当前尺度
    "counts_layer": "counts",                         # 权威原始 counts 所在 layer
    "counts_source": "X" | ".raw.X" | "layers[counts]",  # counts 从何提取
    "counts_validated": True,                         # 是否过非负整数+shape 校验
    "counts_integer_check": "full" | "blockwise",     # 校验方式
    "soupx_layer": "counts_soupx" | None,             # SoupX 分支（仅 nancang）
    "processing_history": [ ... ],                    # 逐步处理记录
    "stage": "01" | "02" | "03",
}
```

**硬约束**：`layers["counts"]` 一经 01 建立，02/03 只读不改；03 归一化后 assert `layers["counts"]` 未变；下游只信契约不猜 `.raw`。

## 八、执行模型

- **规划/架构/合并把关**：opus（主 Agent）。
- **叶子实现 + 自验证 + reviewed 分支**：sonnet（workflow agent，worktree 隔离）。
- **每叶子**：coder 实现（focused pytest + ruff 自验证）→ 独立 code-reviewer（新会话，对抗式）→ 我读 verdict → 自主合并（保护字段除外）。
- **合并串行**：同阶段 notebook 虽文件不同，仍逐个合并 + 合并后跑一次 focused 确认不破链；阶段末 CI 全链验证。
