## 二、P1 结构 / 设计

### 2.1 scripts 目录：三个 `_run_*` 应删除

`_run_07_deg.py` / `_run_09_cnv.py` / `_run_nb_16_trajectory_de.py` 是手动调试残留转正进 git：全库零引用、不在 CI、用 `exec()` 跑单 notebook、彼此近乎复制粘贴、前缀未对齐（仅一个带 `_nb_` 中缀）。功能已被 `run_pipeline_test.py`（标准 nbconvert 跑 01-16）完全覆盖。**删除不影响任何调用方。**

其余脚本判定：
- 保留：`make_test_subset.py`、`env_parity.py`、`deseq2_contrast.R`、`soupx_run.R`、`install_r_github_pkgs.R`、`setup_cuda.sh`、`prefetch-gitleaks.sh`（均为非交互、可复用、被 notebook subprocess 或人工一次性调用）。
- `run_pipeline_test.py`：保留但需（1）改名脱离 `test` 歧义（易与 `tests/` 混淆，不被 pytest 收集）（2）修正 README（称跑 01-06，实跑到 16）（3）硬编码 `/tmp/pipeline_test_outputs` 建议改 `tempfile`。
- `trace_downstream.py`：一次性 CLI 分析工具，若长期用可考虑下沉 `src/` 加测试，暂留 scripts 亦可。

### 2.2 per-dataset notebook 模板化：抽象轴是「QC 策略」不是「来源类型」

多源读入（RDS/H5AD/10X/txt.gz）已被 `io.py::read_with_manifest` 完全吸收，01 里读数据只剩一行。四个 per-dataset notebook（kim/yue/nancang 34 cell，nowicki 13 cell）真实差异是 **QC 策略**（自适应 QC vs 作者已预处理跳过）+ 少数标量（N_MAD、SOUPX_ENABLED、EXPECTED_DOUBLET_RATE、FLAG_HEMOGLOBIN）。kim 与 yue 字节数完全相同，共性代码约 95%。

> **纠偏**：PI 设想的「按来源类型（rds/h5ad/10x）各一个模板」会拆出四个 95% 雷同文件。实际只有 2 个模板值得存在：**full-QC 模板**（kim/yue/nancang）与 **author-preprocessed skip 模板**（nowicki）。抽象轴应为「QC 策略模板 + 数据集参数」。

### 2.3 io.py 45K 过载，建议拆分

承担 5 类职责（格式分发 / obs 列值映射 / 基因 ID 双向同步含 mygene 网络查询 / 临床表关联 / QC 基线 + manifest 校验）。与「薄框架、打开文件从上到下线性可读」目标冲突（1000+ 行需大量翻页）。建议拆：
- 基因 ID 同步（`_sync_*`/`_mygene_*`）→ `gene_ids.py`（最独立可测）
- manifest 加载/校验 → `manifest.py`
- 各格式 reader（`_read_10x_mtx`/`_read_txt_gz`/`_read_rds`）→ `readers.py`
- io.py 只留 `read_with_manifest` 编排主流程

### 2.4 下游模块编号体系易困惑

- 目录 `07_downstream/` 与内部文件编号 `07`–`16` 语义重叠：07 既是目录序位又是目录内首文件序位。README 已声明这些模块彼此无执行先后、均以 `06_annotated.h5ad` 为输入、可单独运行——既是扁平并列，连续递增编号本身就误导（编号暗示顺序，实际无顺序）。建议目录内从 01 重编或加前缀（如 `D01_deg`）。
- `10/10b/10c/10d/10e` 变体：`10d_pseudotime_cytotrace2` 实为「分化潜能打分」非拟时序，塞进 pseudotime 家族名不副实；`10e` 是横向比较。命名把「同类方法变体」和「相关但不同的分析」混为一族。
- 文档隐患：`dpt_pseudotime` 被 README 列为「占位、暂无 notebook 产生」，而 `10_pseudotime.ipynb` 标注工具为「扩散拟时 DPT」，命名暗示它该产该列，实际产生方记为 `pseudotime_monocle3_v1`——README 内部对应关系自相矛盾，待 PI 核实。

### 2.5 Stage 衔接契约脆弱

- 版本化只在文件名生效：obs 列与 uns key 全硬编码 `_v1`（`cell_type_final_v1` 等）；PI 把 OUTPUT_PATH bump 到 v2 后列名/键名仍 v1，06c/07 硬读 `_v1`。契约靠散文声明，无机器可读 manifest。
- `06c` 的 `MAIN_OUTPUT_PATH=06_annotated_v2.h5ad` 与 06 自身 rerun 的 v2 命名冲突（回流 vs 重跑语义不同，同名易混）。
- `04_embedded` 默认 `EMBEDDING_METHODS=["pca","harmony"]` 与正文/06 把 scVI/scANVI 当默认方法的叙述不符；主 UMAP 各 cell 未传 `N_NEIGHBORS/METRIC`，静默用默认 k=15/euclidean，与 PARAMS 不一致。

### 2.6 文档漂移

`_project.md`「子模块（计划中）」表仍写 `src/io/`、`stage1_loaded`、`notebooks/01_*` 等旧命名，与现 `00→06c` + `07_downstream/` 实际结构完全脱节，需更新。
