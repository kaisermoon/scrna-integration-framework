# scRNA-seq 整合分析框架优化方案

> 本方案基于 2026-07-10 四份并行只读审查（前半程 00→03、注释段 04→06c、下游模块 07、scripts 目录）与 PI 五轮方向确认整理而成。**动工前需 PI 逐条终审，通过后方按 PR 分批执行。**
>
> 配套诊断文件：`docs/优化诊断-20260710.md`（含每处 CELL 级问题定位）。

## 一、贯穿全项目的风格铁律（本次确立，写入 CLAUDE.md）

**核心判据：进 src 的只有"无科研价值的技术管道"；一切分析逻辑留 notebook cell，可见、可调、可开关。**

技术管道（进 src）限于四类：
1. LLM 配置与调用（`llm_config.py`）
2. 平台检测收口（`platform.py`：OS / CUDA / Rscript 路径）
3. 启动脚手架（找项目根 + BLAS 线程设置）
4. 跨语言桥接（rds 经 R 读入这一步，待 PI 定是否单列）

分析逻辑（留 notebook cell，重复出现不视为缺陷）：
- 数据读取与字段映射、QC（MAD / scrublet / SoupX）、标准化、细胞周期打分
- 评分指标计算（QC / 聚类 / 整合 / 注释一致性）
- marker 基因加载与筛选
- 所有绘图（留 cell 才能在输出区直接显示）

这条比现有 ADR-0001/0003/0004「薄框架」更进一步：薄框架讲「少写 wrapper」，本铁律限定「wrapper 只允许技术管道两类，其余一律 notebook」。

**开关式裁剪范式**：可选步骤（如 SoupX）整段包在 `if XXX_ENABLED:` cell 里，用则打开、不用则跳过或删除，一眼看清每个 cell 做什么。

**platform 决策可见**：`platform.py` 只放检测函数（收口不重抄），notebook 调用后必须 `print` 出结果（选了什么设备、CUDA 是否可用、Rscript 路径），让决策过程在 cell 里显示。

## 三、P0 正确性缺陷（最高优先，独立成批修，不掺重构）

这几处直接影响跑出来的数字与结论可信度，先修。

### F1 SoupX 校正被静默丢弃

- **位置**：`01_kim` CELL20 附近 `adata[cell_ids].X = corrected`（nancang 开了 SOUPX_ENABLED，同受影响）
- **问题**：对视图（view）赋值，scanpy 下不写回原对象，只弹 warning。矩阵其实没变，但 `ambient_correction_applied=True` 谎报已校正。
- **修改方案**：改为对底层对象显式赋值；校正后加断言（比对校正前后矩阵确有差异）才置 `ambient_correction_applied=True`。此修改在 per-dataset notebook 的 SoupX cell 内完成（不下沉 src）。

### F2 双重标准化风险

- **位置**：`01_nowicki`（作者已归一化）→ `03_normalized` CELL7 无条件 `normalize_total+log1p`
- **问题**：整数检查只采样 `X[:500,:500]` 且仅 warning 不阻断，拦不住二次归一。
- **修改方案**：manifest 声明 `preprocessing_done.normalized` 状态；`03` 读状态决定是否跳过归一；整数检查从「采样+warning」改为「全量判定+阻断」。

### F3 基因 ID 对齐职责放回 per-dataset

- **位置**：`02_merged` CELL8 检测到大小写冲突却建议「回 01 改」，01 从未执行；ensembl/symbol 混用（nowicki 25853 基因 vs 其他 38606）inner join 交集可能坍塌，只 warning 不阻断。
- **修改方案**：每个 per-dataset notebook **结尾断言基因 ID 轴统一**（symbol 统一大写或统一走 ensembl），不满足报错停住，不进 merge。对齐职责前移到 per-dataset，`02_merged` 只做合并不再兜底修复。

### F4 敏感度分析与实际过滤口径一致

- **位置**：`01` CELL12 敏感度曲线用全局 MAD，CELL24 实际过滤在 `PER_SAMPLE_MAD=True` 时用 per-sample MAD
- **问题**：PI 据曲线选 N_MAD 会被误导（曲线与过滤不是同一口径）。
- **修改方案**：`PER_SAMPLE_MAD` 开关同时作用于曲线与过滤两处，统一口径。

## 四、前半程重构（00→03）：per-dataset 对齐 + io.py 拆解

### 核心变化：每来源一个 notebook，io.py 通用调度复杂度消除

`io.py` 45K 的复杂度大半来自「一个函数吃下所有格式」+「obs_mapping/value_mapping 泛化任意字段」。每来源独立 notebook 后这笔通用性税不用交：

- kim（10x）notebook 只写 `sc.read_10x_mtx(...)` 几行，无格式分支
- tsubosaka（rds）notebook 只写 rds 读取（R 桥接这一步待定是否留 src），读进来后处理全在 cell
- 字段映射不再靠字典泛化，每个 notebook 针对自己数据集真实字段名直接写（`adata.obs['cell_type'] = adata.obs['CellType_original']`），眼前可见可改
- **映射决策落 YAML**：notebook 负责看字段/可视化/断言，manifest（YAML）记录最终映射决定，`00_propose_obs_manifest` 辅助生成

### 参考骨架 notebook（全功能演示，按需裁剪）

命名不用 `_` 开头，直接 `01_per_dataset/` 下放一个可运行的全功能范例（命名待 PI 定，如 `01_template_10x.ipynb`）。所有可能用到的步骤各占独立 cell：

1. 启动（一行 src 调用 + print 环境）
2. 读入（该来源格式对应代码）
3. 看字段（打印 obs/var 概览）
4. 应用映射（按 manifest）
5. QC 分布可视化（完整绘图代码在 cell 内）
6. `if SOUPX_ENABLED:` SoupX 校正（含 F1 修正 + 断言）
7. `if SCRUBLET_ENABLED:` doublet 检测
8. MAD 过滤（曲线与过滤同口径，F4）
9. 细胞周期打分（Tirosh 基因表直接写 cell 内）
10. 断言对齐契约（基因 ID 轴、obs schema、归一化状态、原注释保留，F2/F3）
11. 输出 h5ad

新数据集 copy 骨架，不需要的 cell 删掉，需要的开开关、改参数。

### 现有四个 per-dataset notebook 处置

- 现状：kim/yue/nancang 逐行 95% 雷同（kim 与 yue 字节数完全相同），是「空心化套通用模板」的症状，非健康重复
- 处置：按骨架重写，每个补齐自身真实的字段处理/可视化/断言，长出真实差异
- io.py 的读取/映射/校验逻辑随之拆进各 notebook 的 cell

### 02_merged 与 03_normalized

- `02_merged`：对齐前移到 per-dataset 后，此处只做 concat + 合并质控，删掉兜底修复的 warning 逻辑
- `03_normalized`：加 F2 的归一化状态判定与阻断

## 五、后半程重构（04→06c）：方法学卖点真跑起来 + 教学透明

### 04_embedded 降维去批次

- **B1 全方法兼容并比较**：`EMBEDDING_METHODS` 默认覆盖全部（pca / harmony / scVI / scANVI 及后续新增），每种都跑一遍、产出各自 UMAP 与 `integration_metrics`，横向比较后由 PI 目测选定一个。不存在「默认只跑两个」；scVI/scANVI 慢但仍进默认，可用 `if` 开关按需关闭个别方法。
- **UMAP 参数一致**：现主 UMAP 未传 `N_NEIGHBORS/METRIC`，静默用默认 k=15/euclidean 与 PARAMS 不符 → 显式传 PARAMS 值。
- **integration_metrics 计算回 cell**：`scorers.py` 拆回后，整合指标计算过程显示在 04 的 cell 内。

### 05_clustered 聚类

- **B3 双模式推荐兼容**：分辨率推荐提供多种模式（silhouette / 稳定性 / 其他），跑完都出结果，PI 对比后选用，不自动替 PI 定。现「silhouette argmax 恒选最低分辨率」的单一逻辑改为并列出多指标供目测。
- **悬空契约清理**：`silhouette_score`（05 CELL18）声称供 06 降边界置信度但 06 从未用 → 要么 06 接上，要么删除该声称。
- **聚类指标计算回 cell**（scorers 拆解）。

### 06_annotated 注释交叉比对（本次方法学核心）

- **B2 交叉比对按实际方法数动态进行**：有几个方法进比对就比几个，一个也不强求。四方法各自的修复：
  - **marker 注释**：marker 库是 PI 待办；库填了就跑、进比对列，没填就跳过、不进比对（不再是空 dict 假装跑了）。
  - **scANVI**：现因 scvi-tools≥1.0 API 硬禁用是 bug → 修复启用（PI 明确要兼容），有参考图谱时跑、进比对列。
  - **基因集评分**：评了就纳入比对列，没评就不纳入（PI 明确此逻辑）。
  - **LLM 注释**：保留。
  - 结果：比对列数 = 实际成功跑的方法数，混淆矩阵/kappa 对真实存在的列做，不再静默塌缩成一列还要求 ≥2。
- **B7 多模型共识名实一致**：现每 group 只取一个 haiku 退化单模型 → 要么修配置让共识真多模型，要么去掉「共识」表述。此处需 PI 定：默认就想多模型共识，还是默认单模型（省 token）可选开多模型。
- **B5 教学透明修复**：CELL11 `__defaults__=(3,2,120,False,())` 位置元组硬改库内部默认值 → LLM 调用逻辑打包进 `llm_config.py`（PI 已定 LLM 调用进 src），notebook 里一行可读调用，参数显式命名。
- **B6 verdict 解析**：删 CELL27 内联脆弱解析（带前言即判 LOW），改调已有的健壮函数 `_extract_json_from_llm_response`（现为死代码）。此逻辑随 LLM 调用一并进 `llm_config.py`。
- **B8 三处 LLM 调用归并**：06/06b/06c 三处重复且已漂移的 anthropic/openai 分支 + 补端点 + 取 JSON → 统一为 `llm_config.py` 的标准函数（PI 已定）。

### 06b_per_cluster / 06c_subset

- **B4 签名统一**：06 与 06c 调用同一注释函数签名互斥、06c 未打 patch 大概率 TypeError → LLM 调用归并进 src 后，两处走同一标准函数，签名自然统一。
- **06c tissue context**：从硬编码 "gastric mucosa" 改为子集实际类型（其自身 CELL14 已自述该改）。
- **06c 输出命名冲突**：`06_annotated_v2.h5ad` 与 06 自身 rerun 的 v2 语义冲突（回流 vs 重跑）→ 区分命名。

### B9 版本号硬编码（跨 stage）

- obs 列 / uns key 全硬编码 `_v1`，PI bump 文件版本到 v2 后列名仍 v1、下游硬读 v1 → 版本号集中到 PARAMS 常量，列名/键名引用它，避免散落硬编码。此为约定层修改，随各 stage notebook 一并处理。
