# 全仓代码审查总报告

## 执行摘要

**总体 Verdict：BLOCK。** 当前 `main` 不应作为正式科研分析基线继续扩展，也不应直接交给学生据此生成可用于论文的结果。

项目的产品方向是正确的：**notebook 应是生物医学专家的主工作界面**；科学参数、方法选择、PI 决策、关键处理逻辑、中间诊断和失败状态必须在 notebook 中可见、可调、可逐步运行；`src/` 只应承载无科研判断的技术 plumbing。现有 notebook 已具备集中 PARAMS、中文说明、部分 why 注释、可视化、内存断言和检查点等良好基础。

但三路独立审查按根因去重后，仍确认 12 项 Critical、15 项 Important 和 6 项 Minor。最严重的问题不是“代码不够漂亮”，而是以下四类科研可信度断裂：

1. **数据尺度与方法输入不成立**：raw counts、normalized expression 和伪 counts 混用。
2. **统计单位与方法实现错误**：pseudobulk 混合 cell type、SoupX 输入被裁坏、trajectory-DE 没有显著性检验。
3. **人工判断与失败语义失真**：LLM 建议自动进入 final 标签，方法失败仍写正式 checkpoint。
4. **测试与 CI 假绿**：clean-kernel 会直接失败的问题、R 主路径错误和缺产物均未被 required checks 阻断。

在 P0 问题修复并经过真实小型集成验证前，“141 tests passed”“83.82% coverage”或“23-stage 已打通”均不能作为科研有效性证据。

### 审查方法

- 以 `git ls-files` 和 notebook 完整清单为母集，排除数据、运行产物和历史参考代码。
- 逐 notebook 检查 PARAMS、输入输出契约、分析逻辑、统计单位、随机性、隐藏状态、巨型 cell、失败语义、内存和追溯字段。
- 对 29 个 notebook 做 AST 静态语法检查：**0 个语法错误**；另用 ruff F821 定位 clean-kernel 未定义变量。
- 独立运行 Python 测试和静态工具：141 tests passed；ruff 实际 52 项错误；环境 parity 314 项差异。
- 对 R/Shell/YAML 做语法级检查；用 R 最小实验确认 `as.integer(round(matrix))` 会丢失矩阵维度。
- 本报告按**共同根因**合并三份专项报告；相同问题不因出现在多个文件而重复计数。

### 证据标注

- **事实**：可由当前代码、静态工具或最小复现实验直接确认。
- **推断**：由已确认实现推导出的科研或运行影响；具体效应大小仍需真实数据验证。

## Critical Findings

### C1. 不同表达尺度被直接合并，且任一来源的 normalization 状态会控制全部数据

- **位置**：`notebooks/01_per_dataset/01_nowicki.ipynb:cell 3/11/12`；`notebooks/02_merged.ipynb:cell 4/10/26`；`notebooks/03_normalized.ipynb:cell 3/5/7`
- **证据属性**：问题为**事实**；对下游偏差大小为**推断**。
- **问题**：Nowicki 的 `X` 已 normalized，其他来源 `X` 是 raw counts；02 直接 `anndata.concat`。各来源 `preprocessing_done` 又被做集合并集，只要一个来源声明 normalization，03 就对整个 merged 对象跳过归一化，并无条件把混合尺度 `X` 复制为 `layers['counts']`。
- **影响**：HVG、PCA、批次校正和聚类失去共同尺度；normalized 值还会被 scVI、DESeq2、CytoTRACE、CellChat 等当作 counts。所有下游结果均可能系统性失真。
- **建议**：每来源必须显式区分 `counts_available`、真实 `layers['counts']` 和统一的 normalized `X`。无 raw counts 的来源不得伪造 counts；要么追溯原始矩阵，要么限制其参与的方法。预处理状态按来源记录，禁止用并集决定全体行为。

### C2. SoupX 的算法输入、失败语义和下游 QC 三处同时失真

- **位置**：`scripts/soupx_run.R:92-114,152-193,207-234`；`01_kim.ipynb:cell 20/24`、`01_nancang.ipynb:cell 20/24`、`01_yue.ipynb:cell 20/24`
- **证据属性**：代码路径为**事实**；污染估计偏差大小为**推断**。
- **问题**：R 脚本把 raw droplets 裁到 filtered barcode 交集，丢掉 SoupX 估计 ambient profile 所需的空液滴；`autoEstCont/adjustCounts` 失败时仍把未校正矩阵写成 `corrected_counts.mtx`；notebook 替换 `X` 后不重算 QC 指标，后续过滤继续使用校正前的陈旧值。
- **影响**：校正可能方法学上无效、失败可能伪装为成功，且 QC 判据与最终矩阵不一致。污染校正、聚类、marker 和 DEG 都会继承风险。
- **建议**：完整 raw droplets 作为 `tod`、filtered cells 作为 `toc`，只对齐基因轴并报告 raw/filtered 数量；失败默认非零退出，不得生成 corrected 文件；仅在 PI 显式允许时产出命名清楚的 uncorrected fallback 和状态 JSON。校正后重算并并排展示 QC。

### C3. D02 pseudobulk 的统计单位混合，R 入口还会把矩阵降成向量

- **位置**：`D02_pseudobulk_deg.ipynb:cell 5/6/8`；`scripts/deseq2_contrast.R:69-87`
- **证据属性**：两项实现错误均为**事实**；所得 DEG 不可解释为**推断**。
- **问题**：pseudobulk 产物是 `(sample, cell_type)`，但全部 cell type 一起进入仅含 `~ disease` 的 DESeq2 模型；R 侧 `as.integer(round(counts))` 又会移除 matrix `dim` 属性。
- **影响**：不同 cell type 的表达差异与疾病效应混杂；真实运行还可能在 DESeq2 构造阶段直接失败。当前输出不能解释为任何一个细胞类型的疾病 DEG。
- **建议**：以 cell type 为显式外层循环，每类建立 genes x biological donors 的矩阵，检查每组独立 donor 数并运行 `~ covariates + disease`。R 中用 `storage.mode(counts_int) <- "integer"` 保留维度，并断言矩阵、非负、有限、列名与 metadata 同序。

### C4. 04、05、06b 在 clean kernel 下存在确定性运行阻塞

- **位置**：`04_embedded.ipynb:cell 35 line 98`；`05_clustered.ipynb:cell 18 line 64`；`06b_per_cluster.ipynb:cell 3`
- **证据属性**：**事实**，ruff F821 已复核。
- **问题**：04/05 生成字符串时使用未定义的 `m.items()`，实际变量为 `_m`；06b 在定义 `OUTPUT_VERSION` 前用它构造路径和标签列。
- **影响**：核心嵌入比较、聚类比较和逐簇分析会直接 `NameError`。旧 kernel 残留变量可能让错误偶然通过，形成隐藏状态污染。
- **建议**：修正变量名与定义顺序；新增 fresh-kernel 的 PARAMS/setup 轻量执行和最小 AnnData 真实 cell 回归，测试必须走 notebook cell 的真实调用路径。

### C5. 版本化回跑不能保证文件名、标签列和内部元数据一致

- **位置**：`06_annotated.ipynb:cells 2/29/30`；`06c_subset.ipynb:cells 2/5/15/19/22`；`D03:cell 18`、`D04:cell 24`、`D09:cell 19`
- **证据属性**：不一致为**事实**；导致错误追溯为**推断**。
- **问题**：用户 bump `OUTPUT_PATH` 后，多个 obs 列、uns key 和 `adata.uns['version']` 仍写死 v1；06c 同时混用上游粗标签版本和本轮 subset 版本。
- **影响**：v2 文件可能读取旧标签、覆盖旧图表或在内部声明 v1，论文分析无法可靠追溯。
- **建议**：每个 notebook 只保留一个本轮 `OUTPUT_VERSION`；所有输出路径、列和 uns key由它派生。06c 分设 `UPSTREAM_LABEL_VERSION` 与 `SUBSET_OUTPUT_VERSION`，并做 v1→v2 不覆盖回归测试。

### C6. 06 把 LLM 建议或 `Cluster_N` 写入 final 列，并固定声称 PI 已审阅

- **位置**：`06_annotated.ipynb:cells 27/29/30/33/34`
- **证据属性**：自动写入和固定元数据为**事实**；下游证据污染为**推断**。
- **问题**：LLM `HIGH` 标签自动预填并进入 `cell_type_final_*`；无人填写时以 `Cluster_N` 填满同一个 final 列；元数据仍写 `PI reviewed each cluster`。
- **影响**：绕过 PI 最终判断权。下游只检查 final 列非空，可能把自动建议或簇号当真实细胞类型继续分析。
- **建议**：自动结果只写 `cell_type_suggested_*`。仅当决策 CSV 全簇覆盖且 `PI_CONFIRMED=True` 时生成 final；否则写 draft 文件或阻断正式 checkpoint。记录确认文件 hash、确认时间和未决簇，不得固定声称已审阅。

### C7. D11 把所有 HVG 当作 TF，当前 GRN 不具备调控网络语义

- **位置**：`D11_grn.ipynb:cell 7`
- **证据属性**：`tf_names=_hvg_genes` 为**事实**；伪调控链接程度为**推断**。
- **问题**：所有 HVG 均被声明为候选 TF，且优先使用 raw counts，未控制 library size。
- **影响**：受体、结构蛋白和代谢酶会被称为 TF；深度信号可制造广泛伪相关，regulon/hub TF 解释不可信。
- **建议**：PARAMS 暴露物种匹配的 curated TF list、版本和路径，打印命中率；使用明确的 normalized expression。TF list 缺失时硬阻断正式 GRN，不回退为所有 HVG。

### C8. D12 CellChat 使用错误表达尺度，并破坏全部细胞类型标签

- **位置**：`D12_cell_communication.ipynb:cells 8/10`
- **证据属性**：实现为**事实**；通讯概率偏差为**推断**。
- **问题**：raw counts 直接进入 `createCellChat`，R 侧未规范化；`paste0('C', cell_type)` 对所有标签加前缀，而非仅处理纯数字标签。
- **影响**：library size 影响群间通讯比较；`B cell` 会变成 `CB cell`，结果无法与其他 stage 对齐。
- **建议**：采用 CellChat 官方推荐的 normalized data 路径并显示输入诊断；只对纯数字标签加安全前缀，保存双向 map，读回时恢复原标签。

### C9. D14 用训练内 R2 代替显著性，却称为 DEG/FDR 并驱动富集

- **位置**：`D14_trajectory_de.ipynb:cells 0/1/3/4/6`
- **证据属性**：无 p-value/FDR 为**事实**；结果偏倚大小为**推断**。
- **问题**：实际为 `UnivariateSpline` 训练内 R2 排序，没有 null model、p-value、FDR、donor 重复或分支模型；`R2_THRESHOLD` 被称为“显著”并作为富集输入。
- **影响**：R2 不是显著性，同一数据拟合和评估会乐观；论文中称 trajectory-DE 会构成方法与结论错配。
- **建议**：正式路线使用 tradeSeq、GAM/pyGAM 或带样本效应的方法，输出 effect、p-value 和 FDR。当前实现如保留，只能命名为 exploratory trajectory association score，删除 DEG/显著措辞且不得直接作为正式富集输入。

### C10. 00 会把 obs/临床实际值发送外部 LLM，无脱敏和双确认

- **位置**：`00_propose_obs_manifest.ipynb:cells 0/5/7/10`；`notebooks/_llm_proposer.py:74-107`
- **证据属性**：发送内容与缺少闸门为**事实**；真实数据是否含 PHI 未验证。
- **问题**：prompt 包含 obs 和临床表的实际样例值，直接发送到配置的外部 provider；没有敏感列扫描、脱敏预览、数据边界提示或 PI 二次确认。
- **影响**：患者 ID、日期、住院号或罕见组合信息可能外传，属于项目隐私红线。
- **建议**：默认仅发送列名、dtype、唯一值计数和脱敏类别；临床值默认不发送。增加 `ALLOW_EXTERNAL_LLM=False`、敏感列扫描、完整 prompt 预览和 `PI_CONFIRMED_NO_PHI=True` 双闸门。

### C11. 04 明知 counts layer 无效，仍把它交给 scVI

- **位置**：`04_embedded.ipynb:cells 4/18`
- **证据属性**：**事实**。
- **问题**：`layers['counts']` 非整数、`raw.X` 为整数时，代码不覆盖坏 layer，却仍设置 `_counts_key='counts'`。
- **影响**：诊断显示发现有效 raw，实际模型仍训练在已判定无效的 layer；scVI 分布假设被破坏。
- **建议**：数据来源与实际模型输入必须绑定；raw 有效时显式对齐生成新 counts layer，否则阻断。训练前重复断言非负、近整数、无 NaN，并打印最终使用对象。

### C12. required checks 与 smoke runner 会在真实失败时假绿

- **位置**：`.github/workflows/lint.yml:22-38`；`.github/workflows/test.yml:24-64`；`scripts/smoke_run_notebooks.py:115-256`
- **证据属性**：**事实**；已知 F821/R 主路径 bug进入 main 是直接佐证。
- **问题**：ruff/R lintr 后使用 `|| true`；R job 因无 `DESCRIPTION` 实际不运行；runner 使用 `--allow-errors`，不把 return code/缺产物纳入失败，core 失败仍跑 downstream，最终始终退出 0。
- **影响**：绿色 CI 和 `PIPELINE TEST COMPLETE` 不能证明 notebook 可运行或结果真实生成，现有测试数字产生错误信心。
- **建议**：移除假绿；新增 R parse/integration、Shell、notebook F821/契约 job。runner 中 error、非零退出、缺核心字段/新产物均为 FAIL；core 失败后 downstream 标 `BLOCKED`；任一失败最终非零退出。

## Important Findings

### I1. 科学逻辑仍藏在 `src`、R scripts 和 notebook helper

- **位置**：`src/scrna_integration/io.py:25-353`；`scripts/soupx_run.R:115-213`；`scripts/deseq2_contrast.R:58-103`；`notebooks/_llm_proposer.py:31-337`
- **证据属性**：**事实**。
- **问题**：gene ID/基因组位置映射、SoupX/DESeq2 关键参数与 fallback、obs 字段白名单和 merge policy 都在 notebook 外。
- **影响**：PI/学生无法在主界面查看映射率、歧义策略、模型 design、污染先验或冲突处理，也不能逐步调试。
- **建议**：分析逻辑、科学参数和人工确认回到 notebook；`src` 仅保留 LLM transport、平台检测、bootstrap、RDS 读取等纯 plumbing。脚本可负责文件搬运/进程启动，但不得隐藏科研判断。

### I2. 巨型 cell 与 `in dir()` 隐状态破坏逐步调试

- **位置**：`06b:cell 7`（306 行）、`D13:cell 13`（241 行）、`D05:cell 9`（204 行）、`D04:cell 20`（197 行）、`06:cell 27`、`06c:cell 15`；多处 `in dir()`
- **证据属性**：cell 长度和隐状态为**事实**；调试成本为**推断**。
- **问题**：单 cell 同时准备、运行、解析、绘图和保存；旧 kernel 中的临时变量可改变 fresh run 行为。
- **影响**：失败必须整段重跑，难以定位方法还是 IO 出错；医学用户无法安全只重跑一个科研步骤。
- **建议**：按“输入检查→参数→执行→中间 QC→PI 判断→保存”拆成 20–60 行 cells；不以 `dir()` 判断科研结果存在，改读显式 adata 字段或版本化磁盘产物。

### I3. 多个 PARAMS 没有真正控制实现，另有结果敏感常量隐藏在执行 cell

- **位置**：`04:cells 2/18/24`；`D13:cell 13`；`D04/D05` Monocle cells；`D12:cell 10`；`06:cell 27`
- **证据属性**：**事实**。
- **问题**：如 `SCVI_GENE_LIKELIHOOD`、`SCVI_EARLY_STOPPING` 定义后仍硬编码；metacell k、soft-power R2、Monocle partition/close_loop、CellChat min.cells、LLM temperature 等藏在实现内。
- **影响**：用户以为调参生效，实际结果不变；真正影响科研结论的参数反而不可见。
- **建议**：建立参数消费静态检查；所有科学参数进入 PARAMS，说明范围/方向/何时调整；运行前打印最终生效值并写入 run manifest。

### I4. 方法失败或不可用时仍写正式同名 checkpoint

- **位置**：`D02:cell 13`、`D05:cells 12/13`、`D06:cells 14/15`、`D07:cells 10/11`、`D09:cells 18/19`、`D10:cells 20/22`、`D11:cells 15/17`、`D12:cells 21/24`、`D13:cells 19/22`
- **证据属性**：**事实**。
- **问题**：核心方法没运行也生成看似成功的 h5ad；文件存在无法代表方法成功。
- **影响**：下游和人工检查可能消费“原样转存 + skip 标记”，形成伪完成链。
- **建议**：统一四态 `success/skipped_by_user/unavailable/failed`。仅 success 写正式 output；其他状态写诊断 JSON 或 `_incomplete.h5ad`，结尾醒目列出缺失核心字段。

### I5. D09 多组“统计检验”实际只是总体比例范围

- **位置**：`D09_abundance.ipynb:cell 10`
- **证据属性**：**事实**。
- **问题**：未调用已导入的 Kruskal-Wallis/pairwise 检验，仅按组总体细胞比例计算 range，并用 `>5%` 标记“显著”；还绕过 PARAMS 的 `CONDITION_COL`。
- **影响**：没有 sample-level biological replicates，不能作统计推断。
- **建议**：用现成 `proportion_df` 做 sample-level Kruskal-Wallis、事后 pairwise 和 FDR；否则只称描述性 effect-size 排序。

### I6. D01 跨疾病 DEG 仍把细胞当独立重复并混合 cell type

- **位置**：`D01_deg.ipynb:cells 9/10`
- **证据属性**：实现为**事实**；pseudoreplication 偏差为**推断**。
- **问题**：所有细胞直接做 Wilcoxon，没有按 cell type 分层或 donor 聚合。
- **影响**：细胞组成差异和 donor 效应会被解释为表达差异。
- **建议**：明确降级为 exploratory；正式疾病 DEG 路由到修正后的逐 cell type pseudobulk。

### I7. D07 未经实跑验证，D06 的 pseudotime 输出也没有硬契约

- **位置**：`D07:cells 6/7/8/11`；`D06:cell 11`；`07_downstream/README.md:51-64`
- **证据属性**：D07 自述“API 最佳猜测”和 D06 条件写列为**事实**。
- **问题**：CytoTRACE2 的 API、返回格式和权重检测靠猜测；D06 仅在 GPCCA 恰有 `pseudotime` 属性时写列，却被文档声明为真实产物。
- **影响**：方法可能静默跳过，D08/D14 再静默缺方法，仍被描述为“打通”。
- **建议**：在 exact pinned 环境做真实 fixture 验证并锁定 schema；未验证前标 experimental。每个文档声明字段必须有结尾 hard postcondition。

### I8. D10 的 ORA 背景、输入筛选和通路活性尺度不透明

- **位置**：`D10_pathway.ipynb:cells 6/10/16`
- **证据属性**：**事实**；偏倚大小为**推断**。
- **问题**：直接取 top N DEG，不按效应/显著性筛选，未用可检测基因作背景；decoupler 优先 raw counts。
- **影响**：ORA 背景偏差和 library-size 信号可能主导通路排名。
- **建议**：PARAMS 暴露效应/显著性/方向和 background universe；通路活性使用明确 normalized matrix，并在 sample/cell type 层面汇总。

### I9. D13 的 Python 层次聚类距离和 Ward 方法不匹配

- **位置**：`D13_gene_modules.ipynb:cell 7`
- **证据属性**：**事实**。
- **问题**：方阵被直接传给 `linkage`，被解释为 observation matrix；Ward 又要求欧氏距离，而 `1-|rho|` 不满足。
- **影响**：展示的“朴素模块”树不对应预期相关结构。
- **建议**：用 condensed distance + average/complete linkage，或删除临时模块划分，只保留正式 hdWGCNA。

### I10. bootstrap 线程限制可能设置过晚且诊断值不真实

- **位置**：`src/scrna_integration/__init__.py:9-17`；`io.py:16-17`；`bootstrap.py:58-86`
- **证据属性**：**事实**，新进程验证导入 bootstrap 后 NumPy 已加载。
- **问题**：包 eager import 科学栈后才设置 BLAS 变量；`setdefault` 保留用户值，日志却固定打印 4。
- **影响**：服务器线程爆炸风险仍在，用户看到的诊断与实际环境不一致。
- **建议**：最小化 `__init__`，bootstrap 在科学栈前执行；打印实际环境值与来源；若 NumPy 已加载，显著警告设置可能过晚。

### I11. LLM 多 group 路由和 mLLMCelltype patch 缺少真实版本契约

- **位置**：`llm_config.py:299-312,421-557`；`environment.yml:140`；`tests/test_llm_config.py:600-778`
- **证据属性**：配置覆盖和版本矛盾为**事实**；远端实际影响未实测。
- **问题**：同 provider 的不同 group 会被最后 endpoint 覆盖；Anthropic temperature 不生效；patch 声称版本与 pinned 版本不一致，测试只跑模拟模块。
- **影响**：多模型共识可能路由到错误端点，真实包升级后静默跳过。
- **建议**：按 group id 保存完整 endpoint/model/key 绑定；记录实际调用配置；统一 exact version，增加真实包 + 本地 HTTP stub 契约测试，避免 patch 私有 API。

### I12. CI 与生产科研环境不是同一可复现对象

- **位置**：`pyproject.toml:28-95`；`environment.yml:30-279`；`.github/workflows/test.yml:24-64`；`scripts/env_parity.py:153-317`
- **证据属性**：**事实**。
- **问题**：生产用 exact conda pins，CI 用宽泛 `>=`，安装失败还能 fallback；parity 报告 314 项差异，把关键直接依赖和平台噪声混在一起。
- **影响**：CI 绿不能证明生产环境可运行，用户无法从 parity 识别会改变结果的差异。
- **建议**：CI 增加基于环境 spec/constraints 的代表性 job；安装失败硬失败。parity 分直接依赖、批准例外、传递工具链三层，关键漂移非零退出。

### I13. fixture、CUDA 和依赖追踪工具均会在失败时给过强成功信号

- **影响**：换机、GPU 配置和回跑范围都可能被误判，浪费算力或混用旧结果。
- **建议**：所有工具定义机器可读状态和非零失败；fixture 用 CLI/local config + manifest/hash；CUDA 写诊断 JSON；依赖未知时明确 `UNKNOWN`，不得判 safe。

### I14. 文档、README、ADR 示例与项目状态已明显漂移

- **位置**：`notebooks/README.md`、`07_downstream/README.md`；`README.md`、`CONTEXT.md`、`SPEC.md`、`_plan.md`、`_memory.md`

## 最终判断

当前项目已经有一个合适的方向和相当多面向专家的解释性内容，但“notebook 友好”不能只等于注释多、图多或参数集中。真正的交付标准是：**科学输入正确、统计单位成立、参数确实生效、人工判断不可被自动绕过、失败不能伪装成功、每一步都能被生物医学专家看懂并独立复核。**

下一阶段应先按 P0/P1 恢复科研可信度，再统一 notebook 体验；不建议继续增加新分析方法。
